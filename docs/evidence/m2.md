## Live scenarios and independent observations

Fixtures: artifacts/m2-live-complete-gcc, m2-live-complete-sanitize-gcc,
m2-live-complete-clang, m2-live-complete-sanitize-clang. Each is newly created,
owner-only, has one real SQLite store and copied static note, plus an unused M1
profile solely for testing control-socket exclusion. No existing guest is selected.
The Python driver independently constructs wire messages and inspects database
rows; the C crash driver exercises actual storage code in killed child processes.

| Scenario | Outcome in all four runs | Observation |
| --- | --- | --- |
| A — ID is not authority | PASS | Known A read succeeds; known ungranted B receives DENIED |
| B — Host bypass | PASS | Direct store open returns EACCES from Landlock while openat is allowed by seccomp |
| C — Write/revision | PASS | Revision 1 -> 2, independently inspected complete new content |
| D — Stale base | PASS | First write from 2 yields 3; second from 2 gets CONFLICT; first content remains |
| E — READ-only | PASS | READ-only session PUT denied, current object unchanged |
| F — Stale session | PASS | Old handle bytes rejected in new incarnation; fresh acquisition/read succeeds; cross-world challenge rejected |
| G — Reconstruction | PASS | Saved activity starts new incarnation/session, reads current object through current authority |
| H — Revoked activity | PASS | Revoke, replay old activity, restore only activity metadata and restart: access remains DENIED |
| I — Interrupted precommit | PASS | Storage child killed before BEGIN, after staging and just before COMMIT; reopening shows old complete revision |
| J — Commit/ack uncertainty | PASS | Storage child killed after COMMIT before reply; client has no acknowledgement, reopening shows complete new revision exactly once, no retry |
| K — Service/owner boundary | PASS | Key/repository/proc-memory opens EACCES; ptrace/process_vm, service-prlimit, socket/M1-connect EPERM; missing/wrong secret denied; owner opcode on world endpoint INVALID; no extra inherited FDs |
| L — Exhaustion | PASS | Handle/world/queue bounds exercised; owner INSPECT and STOP remain available; unit tests additionally exhaust object/revision/activity/grant/counter limits |

Kernel-denial results are distinct from server DENIED replies. An unsandboxed
trusted test parent reaches the real M1 socket with an invalid request; the native
child cannot create/connect sockets. The parent also receives EPERM attempting
to ptrace the dumpable=0 service. FD 0 is /dev/null; reads from report fd 1 and
fd 4–15 return EBADF. The owner secret never appears in these logs.

Grant updates/revocation occur only between whole synchronous requests. This is
quiescent live revocation, not an asynchronously concurrent M0 drain implementation.
M2 rejects live delegation explicitly. Activity restoration does not restore
memory, grant rows or old handles. Immutable revision rows are real SQLite rows;
no mocks substitute for the store or the kernel sandbox.

The four interruption points use the production store module in a real storage
process with an injected checkpoint callback. The production daemon never enables
that callback and exposes no crash operation. Tests close the client reply path,
kill the process, reopen SQLite and assert old-or-complete-new contents. This is
process-crash evidence, not sudden power loss or a simulation of every I/O failure.
Ordinary injected errors include SQLite authorizer rejection, read-only/query-only
storage, malformed database bytes, invalid packets and resource counters.

## Failed attempts retained

- Initial SQLite pkg-config probe failed because libsqlite3-dev was absent;
  installation was simulated, narrowly approved and recorded separately.
- Main README staged whitespace check failed on a Markdown hard-break. The
  README commit was followed by 5cd4620 removing the whitespace; no history rewrite.
- First native smoke executions failed (native exec exit 123). EXECUTE alone was
  insufficient for this static image; READ_FILE on the same inode fixed it.
  Review also found a launcher setup path that could mask failure with exit 0;
  it was corrected before the full live driver. The smoke commands themselves
  recorded RUN exit 1. Private artifacts/m2-smoke*.py/logs retain attempts.
- Initial GCC analyzer returned make exit 2 with descriptor-ownership warnings
  around dup2/dup3. Explicit result ownership/cleanup fixed them. Initial Clang
  analyzer emitted two dead-store warnings despite exit 0; removed the dead stores.
  Raw logs: artifacts/m2-analyze-gcc.log and m2-matrix-analysis-native-*.log.
- Earlier successful runs (4290/4306 assertions, then 4320) are retained rather
  than overwritten. Final source adds explicit queue send bounds and reruns all
  M2 modes; complete-series logs above are the final implementation evidence.

## Recovery state and limits

All live service/broker/native children created by the harness are stopped. Private
DBs, keys, logs and binaries remain ignored in artifacts/ or out/; no generated
artifact is a source commit. Only libsqlite3-dev was newly installed; rollback
simulation removes only that package. No viewer stack or USB helper was restored.
M1 live viewer reruns: **BLOCKED**, intentionally absent dependency, historical
accepted results preserved. Nested KVM, physical recovery/device/DMA tests and
sudden-power-loss testing: **NOT RUN**. M3–M5: **NOT RUN**.

The host kernel, SQLite/libc, owner and trusted service/launcher remain in the TCB.
No whole-system confinement, native capability kernel, anti-rollback, secure
deletion, stable disk/IPC format, secure kiosk or physical recovery is claimed.
Trusted same-UID processes outside the sandbox can administer files/processes;
metadata/side channels and availability attacks remain. Random handles have
negligible collision probability, not an absolute non-aliasing proof. Lost replies
are reconciled from revisions/content, without durable operation-ID deduplication.
Single-agent code/test/review shared assumptions remain for maintainer challenge.
